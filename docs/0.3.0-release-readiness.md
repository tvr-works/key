## Integrated review and beta limits

This internal review reused the [protocol contract](piv-recovery-contract.md), [earlier scoped review](piv-recovery-ai-review.md), current implementation and focused regressions. It is not an independent cryptographic audit or a proof of all interleavings. No format-byte change is proposed by this release preparation.

- `V3EpochSigningKey` binds capsule authentication to the vault/key/transition context and algorithm labels, derives a domain-separated wrapping key, checks the opened private key against its public key, and leaves fresh epoch keys and durable retry ownership with the epoch builder. The scoped callback does not promise immediate memory zeroization.
- `V3RecoverySnapshot` revalidates public selection before private use, verifies the final epoch/key and manifest authentication, bounds referenced content, opens each entry with its authenticated context, then rechecks selection and exact source bytes. The selected snapshot is not proof of provider-global freshness or a replay of every closed epoch's plaintext equivalence.
- Restore creates fresh Mac authority in a separate destination and validates its full plaintext inventory before selection. Source authority and recovery registrations are not copied into the new vault.
- Registration/adoption budget checks precede signing/publication. Existing graph, depth, entry and aggregate-byte limits remain unchanged. Recovery history accumulates from the earliest active recipient floor; adding a later backup or checkpoint does not reset it. Limits are refusal safeguards, not a promised entry count, history lifetime or automatic rollover mechanism.
- Removing a Mac or recovery key protects later versions on the continuing history. It cannot erase retained copies. An old holder of both signing capabilities may construct a competing history from an old parent; visible competition refuses, but hidden provider history cannot be ruled out. Mac and epoch signatures are separate capabilities held by an authorized Mac, not independent human approvals.
- Hardware administration remains external. Key reads public state and requests PIN/touch agreement; it does not reset, provision or update either physical key. A public inspection is not possession proof or attestation of protected administration.

Physical qualification covers two Apple silicon Macs on macOS 27.0.1 and two independently provisioned YubiKey 5C NFC keys on firmware 5.8.0. macOS 26+ and compatible Yubico firmware 5.3+ remain compatibility targets, not a fully tested matrix. Use disposable data during the beta. Expanding the tested matrix does not require delaying this beta for every combination.

On November 4 the owner accepted the lingering macOS PIN-dialog workaround **for the public beta only**: after timeout/disconnection the operation stops safely, but the user may need to click Cancel to dismiss the dialog. The native unanswered-PIN check stopped at 90.436 seconds; the full normally approved restore finished in 101.151 seconds with the separate five-minute restore budget. The workaround is described in CLI help and the user guide. Revisit it before Stable promotion; this acceptance does not enable Stable recovery.
