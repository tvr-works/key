## What the code review found

Two early setup interruptions could leave a reservation that prevented another attempt, but could not be resumed because its preparation file had not yet been saved. Adoption already had guarded domain cleanup without a CLI route. Registration needed the same restricted cleanup before its anchor became ready for export.

The fixes expose `recovery adopt --abandon <original-operation-id>` and `recovery register abandon <original-operation-id>`. Both require interactive `ABANDON` confirmation and normal Mac authentication. They select exact device-local ownership, refuse competing work and changed ownership, and clear only an unarmed reservation. They preserve the vault, checkpoint and files, do not start another attempt, and never contact a token. Armed adoption, export-ready registration and committed setup cannot be abandoned this way. Missing files after those boundaries still require attention; deleting records is not a recovery procedure.

Rotation already handles a stop before saving its intent: an authenticated ordinary read can release that exact unarmed reservation without publishing or signing again. Explicit rotation resume still refuses an unreadable intent because it cannot establish that the operation was a rotation. A new runtime regression proves the ordinary-read route works.
